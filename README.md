# brief-to-strategy

**ИИ-агент «Стратег Фабрики продуктов»: из размытого брифа — проверяемая продуктовая и коммуникационная стратегия, с сопровождением решения после его принятия.**

Репозиторий содержит инструкции агента, методологию, skills, инструменты и проектное состояние. Он предназначен для работы в агентных средах разработки. Это не самостоятельное приложение или сервис.

> **Статус:** описание архитектуры и планируемого процесса не означает, что каждый компонент уже реализован и проверен. Отмечайте реализованные возможности только после подтверждения запуском/тестом; результаты демонстрационного прогона и ограничения должны быть заполнены фактическими данными.

## 1. Что делает агент

В рамках процесса агент помогает:
1. уточнить задачу, цель, ограничения и критерии успеха;
2. спланировать исследование до начала поиска;
3. собрать и оценить evidence, сохраняя происхождение источников;
4. синтезировать ситуацию, insights, gaps и аналитические выводы;
5. сформировать альтернативы, включая Status quo и Kill, и подготовить рекомендацию;
6. разработать согласованные продуктовую и коммуникационную стратегии;
7. подвергнуть стратегию независимой критике и доработать её;
8. пройти финальную проверку, подготовить план проверки и карточку решения;
9. пересматривать решение при новых данных или триггерах.

**Агент не принимает стратегические решения за человека.** На выборе варианта и утверждении стратегии процесс останавливается и ждёт явного решения.

## 2. Быстрый старт

### 2.1 Требования

Для локальных инструментов требуются Git и Python 3.11+. Для работы агента дополнительно нужна совместимая агентная среда; её установка и авторизация выполняются отдельно. Встроенные скрипты поиска и обработки файлов не требуют API-ключей.

### 2.2 Установка на чистом окружении

Требуются Git и Python 3.11 или новее. Node.js, npm install, .env и API-ключи не нужны для локальных инструментов этого репозитория. Если выбранная агентная среда использует собственные credentials, настройте их в самой среде: репозиторий не загружает секреты из .env.

```
git clone https://github.com/Mnevnis/brief-to-strategy.git
cd brief-to-strategy

python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell (выполнить вместо предыдущей команды):
# .venv\\Scripts\\Activate.ps1

python -m pip install --upgrade pip
python -m pip install -r tools/requirements.txt

# Offline smoke checks:
python -m compileall -q hooks tools
python -m unittest discover -s tests -v
python tools/parse_doc.py --help
python tools/metrics.py --help
```

Команды запускаются из корня репозитория. Для Windows активируйте окружение PowerShell-командой, указанной в комментарии, вместо команды Linux/macOS.
Запустите выбранную агентную среду в корне репозитория. Первый запрос:

```text
Прочитай AGENTS.md и workflow.md.
Возьми проект projects/<project-name>/brief.md.
Выполняй workflow по этапам, используй соответствующие skills,
сохраняй состояние в projects/<project-name>/state/.
После каждого этапа сообщай короткий прогресс.
Остановись на человеческих гейтах и жди моего решения.
```

### 2.3 Проверка первого запуска

- [ ] Агент прочитал `AGENTS.md`, `workflow.md` и нужный skill.
- [ ] Проверил brief и материалы проекта.
- [ ] Создал или обновил state/journal.
- [ ] Выполнил реальный инструментальный вызов, если он необходим текущему этапу.
- [ ] Создал артефакт текущего этапа.
- [ ] Не заявил несуществующую стоимость/возможность.
- [ ] На гейте остановился и запросил решение.

## 3. Как продолжать работу

- **Прогресс:** `projects/<project>/state/journal.md` и сообщения в чате.
- **Остановка:** можно прервать сессию; перед завершением желательно сохранить состояние. При возобновлении агент выполняет Resume Protocol из `workflow.md`.
- **Уточнение:** сообщите дополнительное условие. Агент должен проверить, какие этапы оно затрагивает, и зафиксировать изменение.
- **Исправление:** укажите этап/артефакт и требуемую правку; агент обновляет файл и журнал.
- **Новый чат:** попросите прочитать journal, claims, decisions и продолжить по workflow. Не полагайтесь на память чата.
- **Гейты:** выбор варианта и утверждение стратегии требуют явного ответа.

## 4. Структура репозитория

```text
AGENTS.md                 # принципы, hard rules и границы агента
workflow.md               # единый процесс, этапы, гейты и resume
skills/
  research.md             # планирование и проведение исследования
  analysis.md             # синтез evidence и insights
  options.md              # стратегические альтернативы
  strategy.md             # продуктовая + коммуникационная стратегия
  critic.md               # adversarial review
  revision.md              # обработка findings и доработка
  validation.md            # финальная проверка
  README.md               # каталог skills (если добавлен)
hooks/                    # cost_log.py, action_ledger.py
tools/                    # поиск, загрузка, парсинг и метрики
knowledge/
  methodology/             # методология
  sources/                # реестр/кэш источников, если используется
projects/
  <project>/
    brief.md
    materials/
    state/
      journal.md
      claims.jsonl
      decisions.md
      budget.json
    output/
      research_plan.md
      research.md
      analysis.md
      situation.md
      options.md
      product_strategy.md
      communication_strategy.md
      critic.md
      revision.md
      validation.md
      validation_plan.md
      summary.md
(локальные credentials агентной среды не хранятся в репозитории)
gitignore
README.md
```

Фактическая структура может отличаться; сверяйтесь с содержимым репозитория. Не создавайте пустые папки/файлы лишь для соответствия этому описанию.

## 5. Архитектура и workflow

Подробный процесс и критерии выхода описаны в `workflow.md`.

| Этап | Скилл | Результат |
|---|---|---|
| Intake | — | цель, scope, ограничения и уточнения |
| Research planning | research | план вопросов, источников и проверки |
| Research | research | evidence, источники, claims, gaps |
| Analysis | analysis | situation picture и insights |
| Options | options | альтернативы, сравнение, recommendation |
| Human gate | — | выбор человека |
| Strategy | strategy | product strategy и communication strategy |
| Critic | critic | независимый review |
| Revision | revision | исправления и traceability |
| Critic loop | critic + revision | до 3 циклов |
| Human approval | — | утверждение стратегии человеком |
| Validation | validation | итоговый статус готовности |
| Handoff | validation | validation plan, summary, decision card |
| Support | revision + relevant skills | ревизия при новых данных |

## 6. Skills

Skills — процедурные инструкции, которые задают метод выполнения этапа. Они не заменяют workflow и hard rules.

| Skill | Назначение |
|---|---|
| `research.md` | research question, план до поиска, evidence, качество источников, gaps, claims |
| `analysis.md` | синтез фактов, insight, причины, возможности, приоритеты и ограничения |
| `options.md` | различные альтернативы, trade-offs, критерии, допущения и тесты |
| `strategy.md` | выбранное направление, продуктовая и коммуникационная стратегия, roadmap, KPI |
| `critic.md` | независимый критический обзор и severity/вердикт |
| `revision.md` | disposition findings, правки, change log, unresolved issues |
| `validation.md` | требования, evidence, coherence, feasibility, KPI, риски и готовность |

## 7. Состояние и проверяемость

- `claims.jsonl` — реестр существенных claims с уникальными IDs, источниками, статусами и evidence.
- `decisions.md` — выбор и утверждения человека, rationale, ответственный, метрики и триггеры пересмотра.
- `journal.md` — журнал этапов, состояния, артефактов и возобновления.
- `budget.json` — лимит и журнал вызовов, если usage передаётся в `hooks/cost_log.py`.

Стратегические выводы должны ссылаться на evidence. Синтетические респонденты — только гипотезы; они не доказывают спрос.

## 8. Инструменты, модели и стоимость

Список используемых инструментов и моделей должен соответствовать текущим конфигурациям и результатам проверок. Заполните таблицу после подтверждения реального запуска.

| Компонент | Роль | Проверенный статус / стоимость |
|---|---|---|
| Агентная среда | выполнение workflow | заполнить после проверки |

| Hooks / routing / subagents | автоматизация и специализация | не заявлять без проверки |

## 9. Демонстрация и оценка

Для демонстрационного проекта храните исходный бриф и дату/версию; полный пакет артефактов; журнал и claims (с удалёнными секретами); фактическое время и стоимость; число и характер правок человека; результаты тестов, включая resume, новую задачу, ошибки инструментов и prompt injection; baseline сравнение на том же брифе и сопоставимых условиях, если оно проведено.

Не заполняйте этот раздел обещаниями или оценочными числами до фактического прогона.

## 10. Ограничения

- Модель может ошибаться; evidence и выводы требуют критической проверки.
- Доступность и качество поиска/API зависят от инструментов, тарифов и лимитов.
- Синтетические данные не доказывают спрос.
- План эксперимента не означает, что эксперимент проведён.
- Strategy output не гарантирует коммерческий результат.
- Внешние действия и стратегические решения остаются под контролем человека.
