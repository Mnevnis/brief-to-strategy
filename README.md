# brief-to-strategy

**ИИ-агент «Стратег Фабрики продуктов»: из размытого брифа — проверяемая продуктовая и коммуникационная стратегия, с сопровождением решения после его принятия.**

Репозиторий — рабочее место агента: инструкции, методические знания, инструменты и состояние задачи. Запускается в готовых агентных средах (OpenCode / Claude Code / Cursor) без развёртывания собственных сервисов.

---

## 1. Что это и чем не является

**Это:** папка с инструкциями, знаниями, инструментами и состоянием, которая превращает IDE-агента в продуктового стратега. Агент сам ведёт работу по шагам, использует инструменты, проверяет результат и подключает человека на существенных выборах.

**Это НЕ:** отдельное приложение или сервис; автономная система типа OpenClaw/Hermes; генератор «красивого текста про стратегию».

Что агент выдаёт из запроса:
1. проверяемую картину ситуации — что известно, откуда, чего не знаем;
2. ≥3 содержательно разных варианта, включая «оставить как есть» и «закрыть направление», с сильными возражениями;
3. обоснованную рекомендацию — согласованные продуктовую и коммуникационную стратегии + план проверки;
4. после решения — карточки решений и ревизию выводов при новых данных.

- [ ] создал/обновил `state/journal.md`;
- [ ] вызвал инструмент (поиск или чтение файла);
- [ ] `/cost` показывает ненулевую стоимость.

## 3. Как работать: прогресс, стоп, уточнить, исправить
- **Прогресс:** `state/journal.md` (шаг / сделано / дальше) + строка прогресса в чате после каждого шага; стоимость — `/cost` и `state/budget.json` → `COSTS.md`.
- **Стоп:** Ctrl+C или закрыть терминал. Состояние — в файлах, ничего не теряется.
- **Уточнить:** прервать и написать уточнение — агент учтёт с текущего шага; на гейтах агент спрашивает сам, не более 3–5 вопросов, только важных для следующего шага.
- **Исправить:** «переделай шаг N с учётом <ограничение>» — агент перезаписывает артефакт и фиксирует правку в journal.
- **Продолжить после перерыва** (в т.ч. в новом чате):
  `Прочитай state/journal.md и state/claims.jsonl. Продолжи с шага <N>.`
- **Переносимость:** та же папка открывается в Claude Code (`claude`) или Cursor — AGENTS.md читается автоматически, состояние общее.

## 4. Структура репозитория
```
AGENTS.md                # конституция агента: роль, правила, запреты
workflow.md              # процесс: шаги, гейты, критерии входа/выхода
skills/                  # повторяемые процедуры (research, options, revision…)
hooks/                   # действия по событиям: лог стоимости, чекпойнт
tools/                   # скрипты: поиск, fetch+кэш, парсинг, метрики
knowledge/
  methodology/           # JTBD, unit-экономика, коммуникация, чек-листы
  sources/               # реестр открытых источников + кэш страниц
projects/
  megafon-demo/
    brief.md             # задача (открытый бриф конкурса)
    materials/           # документы, таблицы, скриншоты (открытые данные)
    state/               # journal.md, claims.jsonl, decisions.md, budget.json
    output/              # картина, варианты, стратегии, план проверки
  second-brief/          # проверка обобщаемости
COSTS.md                 # измеренные время и стоимость
BASELINE.md              # сравнение с обычным чатом без агентного слоя
.env.example             # шаблон ключей
README.md                # этот файл
```
Слои раздельны: постоянные инструкции / методология / материалы проекта / состояние задачи (правила смешивания — workflow.md §«Контекст»).

## 5. Архитектура
### 5.1 Процесс (workflow)
1. Intake и уточнение (гейт: вопросы только важные для следующего шага).
2. Сбор материалов: источник → кэш → provenance (URL, дата).
3. План исследования: вопросы, которые могут изменить решение.
4. Картина ситуации: реестр утверждений.
5. Варианты ≥3 + возражения (гейт: человек выбирает).
6. Продуктовая и коммуникационная стратегии (гейт: человек утверждает).
7. План проверки + карточка решения.
8. Сопровождение: ревизия при новых данных.

### 5.2 Контекст и память
- `claims.jsonl`: `{утверждение, источник, дата, статус: факт|гипотеза|прогноз|устарело|отозвано}` — факты отделены от гипотез; прежний ответ агента никогда не становится фактом.
- `decisions.md`: решение, ответственный, метрика, условия пересмотра.
- `journal.md`: журнал действий с идемпотентностью — после сбоя работа возобновляется без незаметных повторов.

### 5.3 Инструменты

## 7. Ключевые решения и их обоснование
- Без собственного оркестратора: среда уже даёт инструменты и цикл; свой фреймворк = стоимость поддержки без пользы.
- Состояние в файлах, не в БД: resume, переносимость и прозрачность для жюри бесплатно.
- Без векторной БД: на нашем объёме хватает индекса + grep, смысл проверяет модель; проще и честнее.
- Курированные источники заранее: меньше блуждания в поиске = дешевле и стабильнее.
- <ДОПИСАТЬ: решения с обоснованием пользы, обсудить обязательно>.
